# SDK 규칙 정적 검사

`CLAUDE.md`의 SDK 규칙 중 **컴파일러가 잡아주지 않는 것**을 Unity 없이 검사하는 도구입니다. 공개 표면, 파사드 리셋 대칭성, 문서-코드 정합성을 봅니다.

## 왜 필요한가

이 SDK에서 조용히 새 나가는 위반은 대체로 세 종류입니다.

- **공개 표면** — `Supabase` 파사드에 `internal` 멤버가 섞이거나, 공개 메서드가 result 타입이 아닌 값을 돌려주는 경우. 컴파일은 통과하고 게임이 쓰기 시작한 뒤에야 문제가 됩니다.
- **리셋 누락** — 파사드 백킹 필드를 추가하면서 `Initialize`의 리셋 블록에 넣는 걸 빠뜨리는 경우. 계정을 바꿔도 이전 상태가 남습니다.
- **문서 드리프트** — 문서가 없는 API를 가리키거나, 시그니처가 바뀐 뒤 예제가 그대로 남는 경우.

`Runtime/Unity`는 UnityEngine 의존이라 컴파일할 수 없습니다. 대신 Roslyn으로 **구문만 파싱**해 선언·수식어·본문 텍스트를 읽습니다. 참조 해석이 필요 없어 UnityEngine 없이도 정확합니다.

## 사용법

```sh
dotnet run --project Tools~/SdkAudit
```

- 종료 코드 `0` = 통과. `1` = 오류.
- 경고는 종료 코드에 영향을 주지 않습니다.

## 검사 항목

| 규칙 | 구분 | 내용 |
|------|------|------|
| R1 | 하드 오류 | `Supabase` 파사드에 `internal` 멤버 없음 |
| R1 | 하드 오류 | 공개 메서드에 `Try` 접두어 없음 |
| R1 | 하드 오류 | 공개 메서드가 result 타입을 반환 (bare value 금지) |
| R1 | 경고 | `Supabase` 외 진입점의 `internal` 멤버 |
| R2 | 하드 오류 | 파사드 백킹 필드가 리셋 블록에서 전부 정리됨 |
| R2 | 하드 오류 | `Reset()`을 가진 파사드는 리셋 블록에서 호출됨 |
| R2 | 하드 오류 | 아무도 부르지 않는 `Reset()` 없음 |
| R2 | 경고 | 파사드를 일부만 정리하는 메서드 |
| R3 | 하드 오류 | 문서가 가리키는 `Supabase.*`가 실제 공개 멤버로 존재 |
| R3 | 경고 | 공개 멤버가 문서에 등장 |
| R4 | 하드 오류 | 문서의 선언형 시그니처 파라미터 이름이 코드와 일치 |

리셋 블록은 이름으로 찾지 않고 **파사드 필드를 가장 많이 `null`로 되돌리는 메서드**를 그것으로 봅니다. 메서드 이름이 바뀌어도 검사가 따라갑니다.

## 예외 목록

`Program.cs`의 `nonFailingMembers`는 값을 돌려주지만 **실패할 수 없어** R1 반환타입 규칙의 대상이 아닌 멤버입니다. 네트워크를 타지 않는 순수 변환·등록 헬퍼만 들어갑니다. 항목을 추가할 때는 정말 실패할 수 없는지 확인하고 근거를 주석으로 남기세요.

## 한계

- 구문 파싱이라 **타입 해석이 없습니다.** 반환 타입 판정은 이름 문자열 기준이므로, result 타입에 별칭을 쓰면 인식하지 못합니다.
- R3 미문서화는 **경고**입니다. 게임이 직접 부르지 않는 배선용 공개 멤버(PlayNANOO 인터셉터 등)는 문서가 없는 게 정상입니다.
- R4는 문서의 `반환타입 Supabase.메서드(...)` 형태만 대조합니다. 호출 예제는 건드리지 않습니다.
- 판단이 필요한 항목(에러 사유의 로그 레벨 분류, SQL 스키마 드리프트, 샘플 최신성)은 자동화 대상이 아닙니다.

## Unity 영향

폴더명이 `~`로 끝나 Unity가 완전히 무시합니다(`.meta` 미생성).
