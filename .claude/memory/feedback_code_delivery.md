코드를 전달하기 **직전에 이 표를 대조한다.** 흩어져 있던 규칙(게시 금지·신규 파일 스레드·3개 이상 전체코드·줄번호 표기)을 한곳에 모은 것이라, 여기만 보면 된다. `CLAUDE.md`의 "Retool 수정 규칙"도 같은 내용이다.

## 전달 방식

| 상황 | 처리 |
|------|------|
| **신규 파일 생성 · 파일 삭제** | 채팅에 코드 금지. `retool_create_or_append_react_app_thread_message`로 **Claude가 직접** 생성/삭제 |
| 기존 파일 · 변경 3곳 이상 | **파일 경로** 명시 + **전체 코드** (부분 편집은 실수 시 디버깅이 어려움) |
| 기존 파일 · 변경 1~2곳 | **파일 경로 + 줄번호** 명시 + 부분 코드 |
| 게시(Publish) | **항상 사용자가 직접.** `retool_publish_react_app` 호출 안 함 |

읽기(`retool_read_react_app_files`)·진단은 자유. Retool 작업은 별도 세션에 미루지 말고 **이 세션에서 직접** 처리한다(2026-07-13 통합 지시).

## 부분 수정 표기

- **파일 경로는 항상.** 응답에 파일이 하나뿐이어도 생략 금지.
- **줄번호는 대략이어도 된다**(2026-07-27 확인 — 조금 스크롤하면 됨). 단 **"바꾸기 전" 코드는 현재 파일과 정확히 일치**해야 한다. 헷갈리면 `retool_read_react_app_files`로 먼저 읽어 그대로 옮겨 적을 것.
- "찾기/교체"·검색 앵커로 줄번호를 대체하지 말 것. 함수명은 줄번호에 덧붙이는 보조일 뿐.
- 로컬 저장소 파일은 Read가 줄번호를 주므로 `파일:줄`(예: `AutoList.cs:89`)로 표기. 로컬은 Edit 툴로 직접 수정하므로 채팅 스니펫이 필요 없다.
- `.md` 문서에는 3곳 이상 전체코드 규칙을 적용하지 않는다(Edit로 개별 처리).

## 반복 실패 모드 (출력 전 반드시 확인)

- **한 응답에 전체 교체와 부분 수정을 섞을 때** 앞 항목이 전체 파일이면 그 형식에 끌려가 뒤의 부분 수정에 줄번호를 빠뜨린다. **코드 블록을 하나씩 "전체냐 부분이냐" 개별 판정**할 것. 앞 항목의 형식은 근거가 아니다.
- **작업 몰입 중 점검 누락** — 설계·코딩에 집중하면 전달 방식을 안 보고 관성으로 출력한다. 2026-07-27 세션에서 ① 부분 수정 줄번호 누락(2회) ② 신규 파일 2개를 스레드가 아닌 채팅 코드로 제공 — 모두 사용자 지적. 규칙이 불명확해서가 아니었다.
- "줄번호 주는 도구가 없다"는 회피는 핑계 — 파일을 읽으면 줄을 셀 수 있다.

**Why:** Retool 파일은 편집 실수 시 디버깅이 어렵고, 임의 게시는 오래된 main 기준 스레드가 다른 작업을 되돌리는 사고를 낸다([[project_retool_thread_publish_hygiene]]). 게시를 사용자가 하는 것은 git 커밋/푸시와 같은 원칙([[feedback_commit_push]]).
