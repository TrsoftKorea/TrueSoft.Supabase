## 운영 콘솔 화면 규칙

비슷한 화면은 같은 꼴로 보여야 한다. 꼴은 **공용 부품(`src/components/ui`)이 정하고**, 화면은 부품을 가져다 쓴다 —
화면마다 클래스를 다시 짜면 굵기·여백·색이 조금씩 갈라진다(2026-10-28 사용자 지적: "어떤 탭은 제목이 굵고 어떤 탭은 설명이 없다").
부품에 없는 꼴이 필요하면 화면에서 짜지 말고 부품을 만들거나 넓힌다.

### 검사로 지키는 것

`npm run check:ui`(`scripts/check-ui.mjs`)가 작업 끝마다 돈다(콘솔 파일이 바뀌었을 때만). 이미 있는 어긋남은
`scripts/check-ui-baseline.json` 에 기준선으로 적혀 있고, **새로 생기면 실패**한다. 고쳐서 줄면 `--update-baseline` 으로
기준선을 줄인다(늘리는 건 거절된다). 남은 곳 전부는 `--list`. 정말 예외면 검사기의 `EXEMPT` 에 이유와 함께 적는다.

| 번호 | 막는 것 | 대신 쓰는 것 |
|---|---|---|
| U1 | 큰 탭 줄을 직접 짬 | `Tabs`(오른쪽 버튼은 `actions`) |
| U2 | 화면을 덮는 창을 직접 짬 | `ConfirmDialog`(되돌리기 어려운 동작) · `EditDialog`(값을 넣는 창 — 폭 `size`, 제목 아래 대상 `description`, 저장 실패 `error`, 아래 버튼 `footer`) |
| U3 | 제목 태그(`h1`~`h6`)를 직접 씀 | `PageHeader`(페이지) · `CardHeader`(카드, 오른쪽 버튼은 `actions`) · `GroupBox`(묶음 상자) · 창 부품의 `title` |
| U4 | 연한 고정색 바탕 `bg-[#연한색]` — 어두운 화면에서 안 바뀐다 | `bg-neutral-50` · `bg-surface` · `bg-brand-soft` 같은 테마 색 |
| U5 | 쪽 넘김 버튼을 직접 짬 | `TableFooter`(왼쪽 건수 `summary` + 오른쪽 쪽 넘김) |
| U6 | 파란·흰 테두리 버튼을 직접 짬 | `Button`(`primary` · `outline` · `dangerOutline`) |
| U7 | 입력칸 꼴을 상수로 다시 정의(이름이 무엇이든 — 내용으로 본다) | `components/ui/Input` 의 `inputCls` · `areaCls`(여러 줄) · `inputCompactCls`(표 안 작은 칸) · `dangerInputCls`(지우기 확인 칸) |
| U10 | 입력칸 태그에 테두리 꼴을 직접 적음 | 위 꼴 뒤에 폭(`w-full` 등)만 붙인다. 꼴에 든 속성(높이·글자 크기 등)을 덧붙이면 이길지 질지가 CSS 생성 순서로 갈려 짐작할 수 없다(`h-auto`·`text-xs` 는 이기고 `h-8`·`h-10`·`text-base` 는 진다) — 다른 크기가 필요하면 꼴을 하나 더 만든다 |
| U11 | 입력칸 이름·표 머리·선택지·버튼·이름 문자열(`label:`·`name:`)에 괄호로 부연 | 괄호를 빼고 단위는 입력칸 옆, 조건은 칸 아래 안내로(아래 「글」) |
| U8 | 브라우저 `alert`·`confirm` | `ConfirmDialog` · `ErrorBanner` |
| U9 | 작은 탭 모양을 화면에서 복사 | `Segmented`(카드 안) · `Tabs`(페이지를 가를 때) |

창은 X · 취소 · Esc 로만 닫는다 — 어두운 바깥을 눌러 닫으면 입력하던 값을 잃는다. 겹친 창은 Esc 가 맨 위 하나만 닫는다.
창 제목에 대상 이름을 "필드 수정 — level"처럼 붙이지 말고 `description` 에 둔다. 저장 실패는 본문 끝이 아니라 `error` 로 —
본문을 스크롤해도 아래 버튼 바로 위에 보인다.

### 배치

- **페이지:** `PageHeader` → (`ErrorBanner`) → 큰 탭(있으면) → 카드들.
- **탭:** 페이지를 가르면 큰 탭 `Tabs`, 카드 안에서 가르면 작은 탭 `Segmented`. 페이지를 가르는데 작은 탭 모양을 쓰지
  않는다(채팅 관리·우편 내역이 그랬다). 큰 탭을 두 줄로 겹치지 않는다.
  성격이 다른 것이 한 탭에 섞이면 탭 이름을 억지로 넓히기보다 안쪽 작은 탭으로 나눈다(설정 › 서비스 연결 › 스토어·로그인).
- **거르기:** 한 화면에 거르기가 둘 이상이면 각각 이름표("기간"·"가입 플랫폼")를 달고 같은 `Segmented` 모양으로
  나란히 둔다 — 하나만 다른 모양이거나 이름표가 없으면 어느 것이 무엇을 거르는지 헷갈린다. 이름표는 버튼 묶음 **위에**
  (`text-xs font-medium text-neutral-500 mb-1`, 입력 칸 이름과 같은 꼴) — 옆에 두면 선택 안 된 버튼처럼 보인다(통계, 2026-10-29 사용자 지적 둘).
- **카드:** `WhiteCard` + `CardHeader`. 제목에는 **설명 한 줄이 반드시** 붙는다. 설정 카드는 `p-5 space-y-5 max-w-2xl`,
  넓은 표가 들어가는 카드만 전체 폭.
- **묶음 목록**(설정 › 서비스 연결 꼴): 묶음마다 `GroupBox`(테두리 상자 + 옅은 바탕 제목 띠). **한 화면에서 함께
  가져오는 값**(같은 키의 ID·파일 등)만 묶음 제목 한 줄 아래 들여 써서 함께 보인다 — 가져오는 곳이 서로 다르면 묶지
  않는다(Sign in with Apple 은 Team ID 가 다른 화면이라 안 묶음, 2026-10-28 사용자 지적). 줄마다 이름 아래에
  **그 값이 무엇인지** 적는다(아래 「글」) — 상자 제목 옆으로 옮기면 다른 상자와 글 위치·결이 갈린다(같은 날 사용자 지적). 상자끼리 칸 폭을 고정해(`table-fixed` + `colgroup`) 상태·버튼이 위아래로 줄을 서게 한다.
  쓰지 않을 수 있는 묶음은 제목 띠 오른쪽(`GroupBox` 의 `actions`)에 "사용" + `Switch` 를 두고, 끄면 내용을 접는다.
  켠 묶음에서 반드시 넣어야 할 값은 이름 뒤에 빨간 `*`, 비어 있으면 빨간 "없음" — 필수가 아닌 빈 값은 회색 "없음"으로
  둔다(빨간색이 섞이면 진짜 빠진 값이 묻힌다, 2026-10-29 사용자 요청).
- **표:** 머리줄 `bg-neutral-50 text-neutral-500 text-xs`. 불러오는 중·빈 목록·실패는 `TableStatusRow` —
  실패를 "없습니다"로 보이게 하지 않는다.

### 버튼

- 역할마다 모양을 하나로 고정한다: **입력·추가·저장 = `primary`(+ 아이콘)**, **바꾸기 = `outline`(연필)**,
  **지우기 = `dangerOutline`(휴지통, 늘 빨갛다)**. `danger` 는 평소 회색이라 옆 버튼과 안 갈린다 — 줄마다 버튼이 늘어서는
  곳에서는 `dangerOutline` 을 쓴다.
- 한 줄에 버튼이 여럿이면 **자리마다 폭을 고정하고, 없는 버튼 자리도 비워 둔다** — 줄마다 위치가 흔들리지 않게.
- 값 하나를 그 자리에서 고치는 **줄 안 편집**은 `inputCompactCls` 칸 + 글자색 아이콘(확인 초록 체크 · 취소 회색 X,
  저장 중엔 도는 표시) — 아이템 카탈로그·우편 분류·플레이어 닉네임이 이 꼴이다.
- 표 칸 안의 버튼·상태 글자는 좁은 칸에서 두 줄로 깨진다. 버튼과 **그 버튼을 담은 `td` 에도** `whitespace-nowrap`,
  상태 글자 칸도 `whitespace-nowrap`. 칸 폭은 최종적으로 들어갈 버튼 전부 기준으로 잡는다.
  글이 길어질 수 있는 칸에는 고정 폭(`w-20` 등)을 박지 말고, 제목처럼 긴 글 칸에는 최소 폭(`min-w-[10rem]`)을 둔다 —
  예약 목록 "대상" 칸이 80px 고정이라 넓은 화면에서도 다섯 줄로 깨졌다(2026-10-28).

### 글

- **글은 이해되는 만큼만 최소로 넣는다.** 버튼·항목(입력칸 이름·선택지·표 머리·탭) 이름에 **괄호로 부연하지 않는다** —
  단위는 입력칸 옆에, 형식·조건은 칸 아래 안내로 뺀다("차단 시간(분)" → "차단 시간" + 칸 옆 "분")(2026-10-28 사용자 규칙).
- **같은 꼴의 글은 성격을 맞춘다.** 한 탭·카드의 설명이 기능 설명이면 같은 꼴의 다른 탭·카드도 기능 설명이다
  (2026-10-28 사용자 규칙). 페이지 설명은 "무엇을 하는 화면인지" 한 문장. 주의할 점은 설명에 섞지 말고 그 동작 옆에 둔다.
- **설명은 두 갈래로만 쓴다.** 값을 넣는 항목 줄(서비스 연결의 키 등)의 설명은 **그 값이 무엇인지**만, 짧은 명사형
  ("iOS 앱의 고유 ID") — 어디에 쓰이는지는 적지 않는다(2026-10-28 사용자 결정, 쓰이는 곳은 카드 설명 한 줄로 충분).
  입력 창 아래 안내는 **무엇을 어떤 형식으로 넣는지**만, "~넣습니다"로 끝맺고 형식은 서버 검사와 맞춘다.
  한 문장에 둘을 섞지 않는다.
- **상태 줄은 정상이면 한마디로, 문제가 있으면 무엇이 문제인지만 짧게** 보인다. 시각·건수·메모 같은 세부는
  "자세히"로 접는다 — 늘 펼쳐 두면 정상일 때도 읽을 글이 많아 문제가 묻힌다(구매 내역 위쪽 자동 작업 줄, 2026-10-28
  사용자 지적). 상태를 못 불러왔으면 "정상"이라 하지 않는다. 주기가 정해진 작업은 실패만이 아니라 **제때 안 돈 것**도
  문제로 본다(요청만 보내는 작업은 안 불려도 실패 기록이 안 남는다).
- **설명에 바로 아래 보이는 탭·칸·종류를 나열하지 않는다** — 화면이 이미 보여 주고, 하나 늘면 설명만 낡는다(통계 설명이
  탭 이름과 어긋나 있었다, 2026-10-28 사용자 지적). "날짜별"처럼 지금 칸들의 공통점을 적는 것도 같다 — 다른 종류가 들어오면
  틀린 말이 된다. 예외는 **바꾸면 화면 밖에서 달라지는 곳**을 알리는 글(설정 › 시간대·서비스 연결)이다. 설정값에 따라 바뀌는
  말(시간대 이름 등)은 글에 박아 쓰지 말고 그 값을 읽어 넣는다.
- **외부 서비스 항목의 이름은 그 서비스 화면에 적힌 표기**를 쓴다 — 운영자가 그 화면에서 같은 글자를 찾는다.
  표기는 그 서비스의 **한국어 공식 도움말**로 확인하고, 거기 없으면 짐작하지 말고 운영자에게 화면 글자를 묻는다.
  한 묶음 안에서는 한 언어로 맞춘다(앱 내 구입 키: Issuer ID · Key ID · Private key — 2026-10-28 사용자 결정).
  "가져오는 방법" 단계 속 따옴표 글자는 묶음 이름과 달라도 그 화면 글자 그대로 둔다.
- 이름을 바꾸면 **같은 이름이 나오는 곳 전부**를 함께 바꾼다 — 운영 기록의 작업 이름, 다른 화면의 오류 안내, 설치 문서.

### 색

- 테마 색(`neutral-*`·`surface`·`brand-soft`)을 쓴다. 테마가 어두운 화면에서 값을 바꿔 준다.
- 흰 글자가 얹히는 색(게임 색 등)은 흰색과 대비 4.5:1 이상 — 화면이 그보다 낮은 색은 저장을 막는다(서버는 형식만 본다).
- 고친 화면은 가짜 데이터 모드에서 **밝은·어두운 화면 둘 다** 본다.
