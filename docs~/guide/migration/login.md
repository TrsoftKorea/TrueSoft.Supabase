# 로그인

## 로그인 호출 {#login-call}

로그인 API는 이관 전·중·후 동일합니다. 자세한 내용은 [인증](/guide/auth/anonymous)을 참고하세요.

플레이나누 로그인이 성공하면 아래 프로퍼티를 사용할 수 있습니다.

| 프로퍼티 | 설명 |
|---------|------|
| `TrueBaseNanoo.UserId` | 플레이나누 uuid. 로그인 전에는 null |
| `TrueBaseNanoo.OpenId` | 플레이나누 openid. SDK가 반환하지 않으면 null |

## 닉네임 {#nickname}

로그인할 때마다 플레이나누 닉네임을 Supabase 닉네임에 덮어씁니다. 수동·자동 로그인 모두 같고, 두 이름이 이미 같으면 아무것도 보내지 않습니다. 게임 코드가 할 일은 없습니다.

Supabase가 그 이름을 거절하면 로그인은 그대로 성공하고 `[PlayNanooRuntime] PlayNANOO 닉네임 … 을 Supabase 에 넣지 못했습니다` 경고만 남깁니다. 다른 유저가 이미 쓰는 이름이거나 금칙어가 든 이름이 이런 경우입니다. 다음 로그인에 다시 시도합니다.

게임에서 `Supabase.SetNameAsync()`로 닉네임을 바꾸면 플레이나누와 Supabase를 함께 바꿉니다. 운영 콘솔에서 바꾼 닉네임은 플레이나누에 반영되지 않으므로, 다음 로그인 때 플레이나누 닉네임으로 되돌아갑니다.

## Android Apple 로그인 {#apple-android}

[Apple 신규 로그인](/guide/social/apple/signin)과 같은 `Supabase.SignInWithAppleAsync()`를 부릅니다. 플레이나누 런타임이 있으면 Android에서는 브라우저 대신 플레이나누 창이 열리고, 받은 토큰으로 Supabase와 플레이나누에 함께 로그인합니다. iOS는 달라지는 점이 없습니다.

Android에서 달라지는 결과는 다음과 같습니다.

| Reason | 설명 |
|--------|------|
| `SupabaseReason.AppleSignInCancelled` | 창을 닫거나 뒤로가기로 나감. 창이 닫힌 뒤 약 2초 안에 옵니다 |
| `SupabaseReason.OAuthLoginInProgress` | 창이 뜨는 중이거나 로그인 처리 중에 다시 누름. 새 창은 열리지 않고, 진행 중인 로그인은 그대로 이어집니다 |
| `SupabaseReason.AnonymousRequiresLink` | 게스트 세션에서 호출함. 게스트 연동은 지원하지 않으니 로그아웃 후 호출합니다 |

::: warning 창이 닫힌 것은 SDK가 짐작합니다
플레이나누 창은 로그인에 성공했을 때만 알려 주고, 닫기·뒤로가기·애플 쪽 실패는 알려 주지 않습니다. SDK는 창이 닫혀 게임 화면으로 돌아온 뒤 토큰이 오지 않으면 취소로 봅니다. 그래서 창을 닫은 뒤 약 2초 동안은 결과가 오지 않습니다 — 로그인을 부를 때 띄운 로딩 표시를 결과가 올 때까지 유지하면, 유저에게는 창을 닫은 뒤 잠깐 로딩하다 풀리는 것으로 보입니다. 이 신호를 주지 않는 기기에서는 결과가 오지 않을 수 있으니, 로딩 화면에 닫기 버튼을 두는 것을 권장합니다. 닫은 뒤 다시 누르면 남아 있던 요청은 취소로 끝나고 새 창이 열립니다. 이때 앞 호출이 받는 취소 결과는 무시하고, 마지막 호출의 결과만 처리하세요. 로그인 처리 중에 다시 누른 호출은 `OAuthLoginInProgress`로 끝나니, 이 결과로는 로딩 화면을 닫지 마세요.
:::

## 게스트 계정 연동 {#guest-link}

[게스트 연동](/guide/social/google/link)은 이관 전과 같은 API를 부릅니다. 플레이나누 쪽은 게스트 계정을 그대로 소셜 계정으로 바꾸므로, 게스트로 쌓은 플레이나누 데이터가 그 계정에 남습니다.

연동하려는 소셜 계정이 이미 다른 플레이나누 계정에 연동돼 있으면 플레이나누가 먼저 거절하고, 결과의 `.ErrorCode`는 `playnanoo_account_already_linked`입니다. 이때 Supabase 쪽은 연동을 시도하지 않아 게스트 상태 그대로입니다. "이미 연동된 계정입니다. 그 계정으로 로그인하면 그 데이터로 플레이합니다"처럼 안내합니다. 그 소셜 계정으로 로그인하면 예전 플레이나누 데이터를 가져오고, 게스트 진행도는 게스트 계정에 따로 남습니다.

::: warning 플레이나누 쪽은 되돌릴 수 없습니다
플레이나누 연동이 성공한 뒤 Supabase 연동만 실패하면, 플레이나누 계정은 소셜 계정으로 바뀐 채 남습니다. 플레이나누에는 되돌리는 기능이 없습니다. 게스트 상태 그대로 다시 연동하면 플레이나누는 건너뛰고 Supabase 연동만 다시 시도하므로, 연동을 다시 누르게 안내하면 됩니다.
:::

## 소셜 계정 추가 연동 {#add-link}

플레이나누 병행 중에는 이미 소셜로 로그인한 계정에 [다른 소셜 계정을 더 연동](/guide/social/google/add)할 수 없습니다. 부르면 아무것도 바꾸지 않고 결과의 `.ErrorCode`가 `playnanoo_add_link_unsupported`로 옵니다. 게임에서는 플레이나누 런타임을 쓰는 동안 추가 연동 버튼을 숨깁니다.

플레이나누 계정에는 소셜 계정이 하나만 연결됩니다. Supabase에만 소셜을 더 붙이면, 그 소셜로 로그인할 때 플레이나누는 이 유저의 것이 아닌 다른 플레이나누 계정으로 들어가 결제·리더보드 같은 플레이나누 기능이 엉뚱한 계정으로 갑니다. 원래 플레이나누 게임에도 없던 기능이라 유저가 느끼는 차이는 없고, 플레이나누 런타임을 걷어내면 다시 쓸 수 있습니다.

게스트가 이 API를 부르면 막지 않고 [게스트 계정 연동](#guest-link)과 똑같이 처리합니다.

## 자동 로그인

`Supabase.TriggerAutoLoginAsync()`는 플레이나누 런타임이 있을 때 두 세션을 모두 복원합니다.

1. Supabase 리프레시 토큰으로 세션 복원
2. 저장된 플레이나누 액세스 토큰으로 `TokenSignIn` 호출. 만료됐으면 저장된 플레이나누 refresh 토큰으로 새 토큰을 받음
3. 둘 다 성공하면 `true` 반환

저장된 플레이나누 토큰이 없거나 복원에 실패하면 Supabase 세션까지 로그아웃한 뒤 `false`를 반환합니다. 두 세션이 항상 동시에 유효하도록 보장하며, 이 경우 게임은 자동 로그인 실패로 받아 명시 로그인으로 유도합니다.

`SignOutFullyAsync()`는 Supabase와 플레이나누 토큰을 모두 삭제합니다.

## 플레이나누 토큰 갱신 {#nanoo-token-refresh}

게임을 켜 두는 동안 `PlayNanooRuntime`·`PlayNanooLegacyRuntime`이 1시간마다 플레이나누 refresh 토큰으로 새 토큰을 받습니다. 게임 코드가 할 일은 없고, 게임에 남은 토큰 갱신 코드는 [지워야 합니다](./install#remove-game-token-code).

- 결제 검증은 플레이나누에 보내기 전에 갱신 시각이 지났으면 먼저 갱신하고, 토큰이 만료돼 실패하면 갱신한 뒤 한 번 다시 시도합니다. 앱을 오래 백그라운드에 뒀다가 돌아와 바로 결제해도 토큰 때문에 실패하지 않습니다.
- 네트워크 문제로 갱신에 실패하면 토큰을 지우지 않고 5분 뒤 다시 시도하며, `[PlayNanooRuntime] PlayNANOO 토큰 갱신 실패` 경고를 남깁니다.
- 토큰이 무효이거나 탈퇴 대기·차단처럼 기다려도 풀리지 않는 실패는 주기 갱신을 멈추고 오류 로그를 남깁니다. 이때는 다시 로그인해야 플레이나누 기능이 동작합니다.
- 로그아웃했거나 탈퇴 등으로 Supabase 세션이 끊긴 동안에는 갱신하지 않습니다.

갱신이 언제 일어나는지 보려면 [진단 › Nanoo Trace](./sync#trace)를 켭니다.
