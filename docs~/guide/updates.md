## 0.6.0 {#v0-6-0}

2026-11-25

- **운영 계정** — 운영 콘솔 **설정 › 운영 계정**에 등록한 계정마다 점검 통과·버전 통과·순위와 통계에서 빼기·원격 설정의 운영 계정 값 받기·우편 시험 발송 받기를 따로 켭니다. 점검 중 통과 목록은 운영 계정의 점검 통과로 옮겨졌습니다. [운영 계정](/guide/app-status/#operators)을 참고하세요.
- **서버가 낮은 버전을 막음** — 최소 버전보다 낮은 앱의 요청을 서버가 거절하고 `SupabaseReason.UpdateRequired`로 실패합니다. 접속 중에 최소 버전을 올리면 1분 안에 세션이 끊기고 `Supabase.OnUpdateRequired`가 발행됩니다. 버전 통과를 켠 운영 계정은 들어갑니다. 업데이트 안내에 숨은 로그인 입구를 두면 운영자가 새 판 출시 전에 확인할 수 있습니다. [업데이트 필요](/guide/app-status/update-required)를 참고하세요.
- **상태 조회의 버전 통과 표시** — `SupabaseAppStatus.VersionAllowed`가 버전 통과 운영 계정으로 로그인해 있는지 알려 주고, 그때는 `UpdateRequired`가 false입니다.
- **약관 동의 기록** — `Supabase.GetLegalVersionsAsync`로 로그인 전에 지금 약관 버전을 읽고, 로그인한 뒤 `SaveLegalConsentAsync`로 동의한 버전과 만 14세 이상 확인을 남깁니다. `GetLegalConsentAsync`의 `NeedsConsent`가 약관이 개정돼 다시 물어야 하는지 알려 줍니다. 동의 기록은 탈퇴해도 남습니다. [약관 버전 조회](/guide/customer-center/legal-versions)를 참고하세요.
- **원격 설정의 운영 계정 값** — 원격 설정 권한을 켠 운영 계정은 운영 콘솔에서 넣은 운영 계정 값이 덮인 설정을 받습니다. [원격 설정](/guide/remote-config/)을 참고하세요.

## 0.5.0 {#v0-5-0}

2026-11-24

::: warning 탈퇴 유예 기간 설정 위치가 바뀌었습니다
`SupabaseSettings`의 `withdrawalRequestDelayDays`를 지웠습니다. 유예 기간은 운영 콘솔 **설정 › 탈퇴**에서 정하고, 기본값은 7일입니다. 7일이 아닌 값을 쓰던 게임은 그 값을 운영 콘솔에 먼저 넣으세요. 플레이나누 병행 게임의 옛 빌드는 플레이나누 쪽 유예를 지운 설정값으로 정하므로, 운영 콘솔 값과 다르면 두 쪽의 삭제일이 갈립니다. 게임 코드에서 이 값을 쓰고 있었다면 그 줄을 지우세요. 플레이나누 병행 샘플을 가져다 쓰는 게임은 샘플을 다시 가져오세요. 옛 샘플은 지운 값을 불러 컴파일되지 않습니다.
:::

::: warning 우편 제목·본문에 값을 넣을 수 없습니다
`Mail.Title`·`Content`가 읽기 전용이 됐습니다. `mail.Title = …`처럼 값을 넣던 코드는 컴파일되지 않습니다. 우편은 [목록 조회](/guide/mailbox/list)로 받은 그대로 쓰세요.
:::

- **점검·최소 버전** — 운영 콘솔 **설정 › 점검·버전**에서 정한 최소 버전과 점검을 `Supabase.GetAppStatusAsync`로 로그인 전에 읽어 업데이트·점검 안내를 띄웁니다. 점검이 시작되면 접속 중인 플레이어도 1분 안에 세션이 끊기고 `Supabase.OnMaintenanceStarted`가 발행됩니다. 점검 중의 호출은 `SupabaseReason.Maintenance`로 실패합니다. [점검·버전](/guide/app-status/)을 참고하세요.
- **본인에게 우편 보내기** — `Supabase.SendMailToSelfAsync`로 게임이 플레이어 자신에게 보상 우편을 보냅니다. 키를 주면 계정마다 한 번만 보내집니다. 접속 때 소급 보상을 우편으로 확인하고 받게 할 때 씁니다. [본인에게 보내기](/guide/mailbox/send-to-self)를 참고하세요.
- **개인정보처리방침·이용약관 창** — `Supabase.OpenPrivacyPolicyAsync`·`OpenTermsAsync`로 운영 콘솔에서 게시한 방침·약관을 게임 위 창으로 엽니다. 로그인하지 않아도 열립니다. [개인정보처리방침 열기](/guide/customer-center/privacy)를 참고하세요.
- **탈퇴 유예 기간을 운영 콘솔에서** — 게임 안 탈퇴 예약과 고객센터 웹의 계정 삭제가 운영 콘솔에서 정한 같은 유예 기간을 씁니다. 이미 깔린 옛 빌드의 탈퇴 예약도 이 기간을 따릅니다. [탈퇴 처리](/guide/withdrawal/)를 참고하세요.
- **우편 제목·본문을 기기 언어로** — `Mail.Title`·`Content`가 기기 언어로 쓴 제목·본문을 돌려줍니다. 그 언어의 글이 없으면 기본 언어 글입니다. 전에는 늘 기본 언어 글이었습니다. 게임 안에서 고른 언어로 보이려면 지금처럼 `TitleFor`·`ContentFor`를 쓰세요. [다국어 메시지](/guide/mailbox/localized)를 참고하세요.
- **비슷한 언어 코드로 찾기** — `TitleFor`·`ContentFor`가 `pt-BR`은 `pt`로, `zh`는 `zh-CN`으로 찾고, 대소문자·`_`를 가리지 않습니다. `"Korean"` 같은 유니티 언어 이름도 읽습니다. 전에는 코드가 똑같아야 찾았습니다.
- **클래스 생성기의 `object` 타입 처리** — 예전 CSV `타입` 열에 `object`가 적혀 있어도 열거형·클래스 자리를 그 값으로 채우지 않고 기존 클래스 파일의 이름을 지킵니다.
- **방침 본문의 이메일 링크** — Android 게임 안 창에서 `mailto:` 같은 웹 주소가 아닌 링크를 기기의 앱으로 엽니다. 전에는 창 안에서 오류 화면이 떴습니다.

## 0.4.3 {#v0-4-3}

2026-11-24

::: warning 0.4.2 생성기로 다시 생성하지 마세요
운영 콘솔이 열거형·클래스 자리를 이름 없이 적습니다. 0.4.2 클래스 생성기는 이 자리를 채우지 못해 컴파일되지 않는 코드를 만듭니다. 유저 데이터 클래스를 다시 생성하기 전에 0.4.3으로 올리세요.
:::

- **열거형·클래스 이름은 게임 쪽에서** — 운영 콘솔에서는 열거형·클래스를 종류만 고르고, 클래스 생성기가 이름을 CSV `타입` 열이나 기존 클래스 파일에서 채웁니다. [리스트·딕셔너리 필드의 타입](/guide/user-data/class-gen#collection-type)을 참고하세요.
- **CSV 타입 차이 경고** — 운영 콘솔에서 정한 구조·원소 타입과 다른 타입을 CSV에 적으면, 불러올 때 그 부분을 쓰지 않는다고 알립니다. 전에는 말없이 건너뛰었습니다.
- **`long` 키 딕셔너리 원소 지급 범위** — `long` 키 딕셔너리 원소를 `int` 범위를 넘는 키까지 서버가 지급합니다. 0.4.2 이하 빌드는 `int` 범위 안의 키만 받고, 넘는 키가 든 우편은 받지 못한 채 남습니다.
- **기존 클래스 파일의 컬렉션 타입 유지** — 다시 생성할 때 기존 클래스 파일에서 컬렉션 필드의 타입을 읽어 유지합니다. 전에는 `[AutoDefault]`나 초기값이 붙은 필드의 타입을 읽지 못했습니다.

- **핸들러 예외를 실패 결과로** — 우편 아이템 핸들러가 예외를 던지면 받기 호출이 예외로 끝나지 않고 `SupabaseReason.MailItemHandlerFailed` 실패를 돌려줍니다. 우편은 이미 수령된 상태입니다.

`SupabaseSettings`의 `duplicateSessionPollSeconds`·`duplicateSessionActionCheckCooldownSeconds`를 지웠습니다. 게임 코드에서 이 값을 쓰고 있었다면 그 줄을 지우세요. 접속 확인은 60초로 고정되고, 중복 로그인 감지는 늘 켜져 있습니다.
:::

- **다른 기기 로그인 즉시 거절** — 다른 기기에서 같은 계정으로 로그인하면, 옛 기기의 다음 요청을 서버가 그 자리에서 거절합니다. 앱으로 돌아올 때도 바로 확인합니다. [중복 로그인 감지](/guide/auth/duplicate-login)를 참고하세요.
- **저장 중 접속 확인 생략** — 세이브 저장이 성공하면 접속 확인을 60초 미룹니다. 저장이 이어지는 동안에는 접속 확인 요청이 나가지 않습니다.
- **자동 로그인 중복 감지** — 다른 기기가 쓰고 있는 계정을 자동 로그인으로 되살리면 `SupabaseReason.DuplicateLogin` 실패로 알립니다.
- **우편 보상 서버 지급** — 우편 보상 키가 숫자 데이터 필드 이름과 같으면, 받을 때 서버가 그 필드에 더합니다. 처리기는 더하기만으로 안 되는 보상에만 등록하면 됩니다. [아이템 핸들러 등록](/guide/mailbox/item-handler)을 참고하세요.
- **세이브 변경 확인 메모리 절감** — 세이브 변경을 확인할 때 쓰는 메모리를 줄였습니다.
- **가이드 실사용 예시** — 가이드의 함수 페이지마다 실사용 예시를 넣었습니다.
