# 유저 데이터

게임 진행 상황(레벨, 골드, 아이템 등)을 서버에 저장하고 기기 간 동기화하는 기능입니다.

## 동작 방식 {#how-it-works}

`StaticUserSave<TRow>`는 유저 데이터를 관리하는 기반 클래스입니다. 변경된 필드만 서버에 전송하며, 쿨타임 배치로 불필요한 요청을 줄입니다.

| 동작 | 설명 |
|------|------|
| Diff 패치 | 이전 상태와 비교해 변경된 필드만 서버에 전송합니다. 변경이 없으면 네트워크 요청을 생략합니다. |
| 쿨타임 자동 저장 | 프로퍼티 값을 바꾸거나 컬렉션을 수정하면 `SupabaseRuntime`이 쿨타임 주기로 자동 업로드합니다. |
| 즉시 저장 | `Supabase.SaveNowAsync()`는 쿨타임을 무시하고 변경분을 즉시 전송합니다. |

세이브 클래스는 [클래스 생성](/guide/user-data/class-gen)으로 만들고, 값은 [읽기 / 쓰기](/guide/user-data/read-write)로 다룹니다.

## 저장 횟수 확인 {#save-count}

저장이 생각보다 자주 나갈 때 원인을 가르는 로그입니다. 씬에 `SupabaseRuntime`이 있으면 저장 시도가 있고 1분이 지날 때 콘솔에 요약을 남기고, 저장 시도가 없으면 남기지 않습니다. `SupabaseSettings`의 `enableApiResultLogs`를 끄면 세지도 남기지도 않습니다.

```text
[Supabase.UserData.SaveSummary] 60초간 저장 24회 · 자동 긴급 20 · 자동 보통 2 · 자동 느림 0 · 게임 직접 호출 2 · SDK 내부 0 (쿨타임 긴급 1초 · 보통 5초 · 느림 30초)
[Supabase.UserData.SaveSummary] 저장에 실린 칸 4개 — 긴급: idle_time 20, level 1 / 보통: stage 3 / 느림: gold 22
```

| 항목 | 설명 |
|------|------|
| 자동&nbsp;긴급·보통·느림 | 자동 저장이 보낸 횟수. 한 번에 보낸 값 중 가장 높은 우선순위로 셉니다. |
| 게임&nbsp;직접&nbsp;호출 | 게임이 부른 저장 메서드가 보낸 횟수 |
| SDK&nbsp;내부 | 앱 전환·로그아웃처럼 게임이 부르지 않았는데 SDK가 보낸 횟수 |
| 실패 | 네트워크 재시도까지 실패한 전송 횟수. 실패가 있을 때만 나옵니다. |

저장 횟수는 앞의 항목들을 더한 값이고 실패는 포함하지 않습니다. 보낼 변경이 없어 요청하지 않은 경우는 세지 않고, 네트워크 오류로 자동 재시도한 저장은 한 번으로 셉니다. 실패한 변경은 다음 전송에 다시 실리므로, 그 전송이 성공하면 실패와 저장 횟수에 각각 1씩 더해집니다. 앱을 끄기 직전에 보낸 저장과 아직 1분이 안 된 횟수는 남지 않을 수 있습니다.

자동 긴급이 많으면 우선순위가 `DataSavePriority.Urgent`인 칸이 자주 바뀌는 것이고, 게임 직접 호출이 많으면 저장 메서드를 자주 부르는 것입니다. 괄호 안은 지금 적용된 쿨타임입니다.

둘째 줄은 그 시간에 성공한 저장에 어느 칸이 몇 번 실렸는지입니다. 우선순위별로 묶고 그 안에서 많이 실린 순으로 놓으며, 값은 남기지 않습니다. 저장 한 번에 여러 칸이 실리므로 칸별 횟수를 더해도 저장 횟수와 같지 않습니다. 칸이 많으면 여러 줄로 나뉩니다.

저장 횟수를 줄이려면 가장 높은 우선순위 묶음에서 횟수가 큰 칸부터 봅니다. 위 예시에서 자동 긴급 20회는 `idle_time`이 끌고 갔으니, 자주 바뀌어도 되는 값이면 [클래스 생성기의 저장 주기](/guide/user-data/class-gen#column-list)를 길게로 바꾸고 다시 생성합니다. `gold`처럼 이미 느림인 칸의 횟수가 큰 것은 다른 칸의 저장에 함께 실린 것이라 원인이 아닐 수 있습니다.

::: warning
생성된 파일의 `[DataColumn]` 우선순위만 고치면 쿨타임은 그대로이고 로그의 묶음만 바뀝니다. 스칼라 칸의 쿨타임은 프로퍼티가 부르는 `MarkDirty`의 우선순위로 정해집니다. 생성기로 다시 생성하면 둘이 함께 바뀝니다.
:::

## 메서드

| 메서드 | 설명 |
|--------|------|
| [`LoadUserSaveAsync`](/guide/user-data/load) | 서버에서 세이브 불러오기 |
| [`SaveNowAsync`](/guide/user-data/save-now) | 변경분 전송 후 완료 대기 |
| [`RequestSave`](/guide/user-data/request-save) | 대기 없이 저장 요청 |
| [`SaveIfChangedAsync`](/guide/user-data/save-if-changed) | 변경된 필드만 저장 |
| [`DeleteUserSaveAsync`](/guide/user-data/delete) | 내 세이브 행 삭제 |
